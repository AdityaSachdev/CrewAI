# CrewAI Projects

A collection of hands-on [CrewAI](https://crewai.com) multi-agent projects — each one a self-contained crew that demonstrates a different pattern for orchestrating AI agents.

These projects were built while working through **Ed Donner's** [AI Engineer Agentic Track: The Complete Agent & MCP Course](https://www.udemy.com/course/the-complete-agentic-ai-engineering-course/) (CrewAI week). They follow the same project structure and learning goals as the companion repo [ed-donner/agents](https://github.com/ed-donner/agents).

## Projects

| Project | What it does | Key concepts |
|---------|--------------|--------------|
| [**debate**](debate/) | Two debators argue for and against a motion; a judge picks the winner | Sequential process, multi-LLM routing |
| [**coder**](coder/) | A Python developer agent writes and executes code to solve a math problem | Safe code execution (Docker), single-agent crew |
| [**analyst**](analyst/) | Finds trending companies in a sector, researches them, and picks the best investment | Hierarchical process, manager delegation, memory, web search, structured outputs |
| [**engineering_team**](engineering_team/) | Lead, backend, frontend, and test engineers collaborate to build a full mini-app | Sequential pipeline, design → code → UI → tests |

## Repository structure

```
crewai/
├── .env                  # Shared API keys (not committed)
├── debate/               # Propose / oppose / judge debate crew
├── coder/                # Code-writing agent with Docker execution
├── analyst/              # Stock-picker crew with memory & search
└── engineering_team/     # Multi-engineer software delivery crew
```

Each project is an independent Python package with its own `pyproject.toml`, virtual environment, and `src/<project>/` layout generated by CrewAI.

## Prerequisites

- **Python 3.10–3.13**
- **[uv](https://docs.astral.sh/uv/)** — dependency and environment management
- **[CrewAI CLI](https://docs.crewai.com)** — install globally:

  ```bash
  uv tool install crewai --python 3.12
  ```

- **Docker Desktop** — required for the `coder` project (safe code execution)
- **API keys** — see [Environment variables](#environment-variables) below

## Quick start

1. Clone this repository and create a `.env` file at the repo root with your API keys (see [Environment variables](#environment-variables)).

2. Pick a project, install dependencies, and run:

   ```bash
   cd debate          # or coder, analyst, engineering_team
   uv sync
   crewai run
   ```

3. Outputs are written to each project's `output/` directory (and sometimes `data/` for memory in `analyst`).

## Environment variables

Place a `.env` file at the **repository root** (or inside the project directory). CrewAI loads it automatically.

| Variable | Used by | Purpose |
|----------|---------|---------|
| `OPENAI_API_KEY` | All projects | OpenAI models (e.g. `gpt-4o-mini`) |
| `ANTHROPIC_API_KEY` | `analyst`, `debate` | Claude models |
| `GOOGLE_API_KEY` | `analyst`, `debate` | Gemini models |
| `SERPER_API_KEY` | `analyst` | Web search via SerperDevTool |

## Customization

Every crew follows the same CrewAI layout:

- `src/<project>/config/agents.yaml` — agent roles, goals, backstories, LLM assignments
- `src/<project>/config/tasks.yaml` — task descriptions, expected outputs, output files
- `src/<project>/crew.py` — crew assembly, tools, process type, memory
- `src/<project>/main.py` — runtime inputs (sector, motion, requirements, etc.)

Edit `main.py` to change the default inputs, or pass inputs programmatically when calling `kickoff()`.
